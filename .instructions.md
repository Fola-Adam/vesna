---
name: Frontend Coding Standards
description: Comprehensive guidelines for writing maintainable, accessible, performant, and production-ready frontend code. These standards ensure consistency, quality, and scalability across the Vesna project.
instructions: |
  Follow these standards in all frontend development (.html, .css, .js, .tsx, .vue) and related backend (Netlify functions). They promote best practices for accessibility, performance, maintainability, and user experience.

  ### 1. General Principles
  - **Code Quality**: Write clean, readable code. Use consistent naming (camelCase for JS, kebab-case for CSS classes, PascalCase for components). Avoid magic numbers; use named constants.
  - **Documentation**: Comment complex logic. Use JSDoc for functions. Keep READMEs and SPEC.md updated.
  - **Version Control**: Commit frequently with descriptive messages. Use feature branches for new work.
  - **Testing**: Manually test features before marking complete. Use browser dev tools for debugging.
  - **No Incomplete Code**: Never commit 'TODO', 'FIXME', or empty handlers. Implement or remove placeholders.

  ### 2. HTML Standards
  - **Semantic Structure**: Use semantic elements (<header>, <nav>, <main>, <section>, <article>, <aside>, <footer>). Avoid generic <div> overuse.
  - **Accessibility**: Include alt text for images. Use aria-label for icon buttons. Ensure keyboard navigability (tabindex only when necessary).
  - **Performance**: Lazy-load images with loading="lazy". Minimize DOM depth. Use data attributes for JS hooks instead of classes.
  - **Validation**: Ensure valid HTML5. No unclosed tags or invalid attributes.
  - **Forms**: Use proper input types (email, tel). Include labels and fieldsets. Provide validation messages.

  ### 3. CSS Standards
  - **Methodology**: Use a design system with CSS variables for colors, fonts, spacing. Follow BEM or similar for class naming (e.g., .product-card__title).
  - **Responsiveness**: Mobile-first approach. Use media queries for breakpoints. Test on multiple devices.
  - **States**: Define :hover, :active, :focus for all interactive elements. Use :disabled for inactive states.
  - **Performance**: Avoid !important. Minimize specificity wars. Use CSS Grid/Flexbox over floats.
  - **Accessibility**: Ensure 4.5:1 contrast ratio. Avoid color-only indicators. Support reduced motion with prefers-reduced-motion.
  - **Organization**: Group related styles. Use comments for sections. Keep styles modular.

  ### 4. JavaScript Standards
  - **Modularity**: Use ES6+ features (const/let, arrow functions, modules). Organize code into single-responsibility functions/objects.
  - **Error Handling**: Wrap async code in try/catch. Provide user-friendly error messages.
  - **Performance**: Debounce/throttle event listeners. Avoid blocking operations on main thread.
  - **Security**: Sanitize user inputs. Never expose API keys in client code.
  - **State Management**: Use localStorage judiciously. Ensure data persistence without corruption.
  - **Events**: Use addEventListener. Clean up listeners on component destruction.

  ### 5. Accessibility Standards
  - **WCAG Compliance**: Aim for AA level. Test with screen readers (NVDA, JAWS).
  - **Keyboard Support**: All interactions work without mouse. Skip links for navigation.
  - **Color and Contrast**: No color blindness barriers. High contrast mode support.
  - **Media**: Captions for videos. Transcripts for audio.
  - **Forms and Inputs**: Clear labels, error states, progress indicators.

  ### 6. Performance Standards
  - **Loading**: Optimize images (WebP format, compression). Bundle JS/CSS. Use code splitting.
  - **Runtime**: Minimize reflows/repaints. Use requestAnimationFrame for animations.
  - **Network**: Cache static assets. Use CDN for fonts/libraries.
  - **Metrics**: Aim for <3s initial load. Monitor with Lighthouse.

  ### 7. Backend (Netlify Functions) Standards
  - **Data Integrity**: Ensure API responses match UI expectations. Handle errors gracefully.
  - **Security**: Validate inputs. Use environment variables for secrets.
  - **Performance**: Optimize queries. Cache where possible.
  - **Logging**: Log errors for debugging. No sensitive data in logs.

  ### 8. Tooling and Workflow
  - **Linting**: Use ESLint for JS, Stylelint for CSS. Fix all warnings before commit.
  - **Build**: Use Netlify for deployment. Ensure builds pass.
  - **Collaboration**: Code reviews required. Discuss UI/UX decisions.

  ### Enforcement
  - Review code against these standards during audits.
  - If a standard is violated, provide justification or fix it.
  - Update this document as the project evolves.
