---
name: UI Audit Checklist
description: A comprehensive, step-by-step checklist for auditing frontend UI/UX completeness, responsiveness, accessibility, and functionality. Use this prompt to systematically evaluate and ensure production-ready interfaces.
prompt: |
  Perform a thorough UI/UX audit on the specified component/page/feature using this detailed checklist. For each item, check the code, test interactively if possible, and note any issues or confirm compliance. Flag incomplete implementations and suggest fixes.

  ### 1. Functional Completeness
  - [ ] No 'TODO', 'FIXME', or placeholder comments in the code.
  - [ ] All event handlers (e.g., onClick, onSubmit) have meaningful implementations, not empty functions.
  - [ ] Dummy or mock data is replaced with real data sources (e.g., API calls, localStorage).
  - [ ] Async operations (API fetches, form submissions) include proper error handling and loading states.
  - [ ] Data flow from backend (e.g., Netlify functions) matches UI expectations (e.g., if UI needs 'username', ensure function returns it).

  ### 2. Interactive Elements Audit
  - [ ] All buttons, links, and inputs have hover states defined in CSS.
  - [ ] All interactive elements have active (pressed) states.
  - [ ] All focusable elements (buttons, inputs, links) have visible focus indicators for keyboard navigation.
  - [ ] Form inputs provide real-time validation feedback (e.g., error messages on invalid input).
  - [ ] Loading indicators (spinners, skeletons) appear during async actions and disappear on completion.
  - [ ] Success/error messages are displayed for user actions (e.g., "Saved successfully" after form submission).

  ### 3. Layout and Responsiveness
  - [ ] Layout uses responsive units (%, vw, rem) and flexbox/grid for adaptability.
  - [ ] No horizontal scrolling on mobile devices (test breakpoints: <640px, 640-1023px, 1024-1279px, >1280px).
  - [ ] Padding, margins, and alignment are consistent across the page/component.
  - [ ] App shell (navbar, footer, sidebar) is consistent across all routes/pages.
  - [ ] Text doesn't overflow containers; line heights and font sizes scale appropriately.
  - [ ] Images and media are lazy-loaded with proper alt text.

  ### 4. Accessibility (a11y)
  - [ ] All images have descriptive alt attributes.
  - [ ] Icon buttons have aria-label or aria-labelledby attributes.
  - [ ] Color contrasts meet WCAG standards (e.g., 4.5:1 for normal text).
  - [ ] Semantic HTML is used (e.g., <button> not <div>, <nav>, <main>, <aside>).
  - [ ] Keyboard navigation works (Tab order, Enter/Space for activation).
  - [ ] Screen reader support: aria-expanded, aria-hidden, role attributes where needed.
  - [ ] Focus management: Modals trap focus, return focus on close.

  ### 5. Visual Polish and Performance
  - [ ] No overlapping text or elements in any viewport.
  - [ ] Flexbox/grid layouts don't break (no unintended wrapping or stretching).
  - [ ] Low-contrast colors are avoided; ensure readability in light/dark modes.
  - [ ] Animations/transitions are smooth (400ms max) and purposeful.
  - [ ] CSS is optimized: No unused styles, efficient selectors.
  - [ ] Page load performance: Images compressed, fonts subsetted, critical CSS inlined.

  ### 6. Interactivity and User Flow
  - [ ] "Happy path" of the feature is fully clickable without dead-ends (e.g., buttons link to valid routes).
  - [ ] Routing is correct; no 404s or broken links.
  - [ ] State persistence works (e.g., form data survives page refresh if needed).
  - [ ] Cross-browser compatibility: Test in Chrome, Firefox, Safari, Edge.
  - [ ] Mobile gestures (swipe, pinch) work if applicable.

  ### Audit Summary
  - List all issues found with severity (Critical, Major, Minor).
  - Provide code fixes or implementation suggestions for each.
  - Confirm if the component/page is ready for production or needs further work.
  - If incomplete, prioritize fixes based on user impact.

  Start the audit by reading the relevant files (HTML, CSS, JS) and running the local server if needed.
